# 安全与发布合规

> **适用**：上线前必接能力、代码加固、资质备案、审核红线。
> **源文档**：`docs/develop/guide/safety-guide-dir/`（2 篇）、`docs/guide/minigame/essential-skills.md`、`docs/operation/norms/`（20 篇）、`docs/guide/minigame/`（备案/资质/适龄）。
> **关联**：加固工具操作见 `devtools.md`。

## 一、必接能力（缺一项就打回）

| 能力 | 适用 | 说明 |
|---|---|---|
| **侧边栏复访** | **所有**小游戏 | 无例外。影响推荐权重，接入方式见 `api-recipes.md` 第 8 节 |
| **客服能力** | **内购**游戏 | 抖音 IM 客服（仅抖音 App）或抖音客服平台（全端 + 支持第三方推送） |
| **敏感词** | 存在用户自定义输入 | 昵称/聊天/签名等输入必须过滤，用 `tt.onKeyboardInput` 等键盘接口配合服务端词库 |

## 二、代码加固

三种手段，可叠加：

| 手段 | 作用 | 代价 |
|---|---|---|
| 代码混淆 | 标识符重命名、控制流打散，防逆向 | 包体增大（低/中/高约 102%/128%/170%）、轻微性能损失 |
| 代码加固 | 在混淆基础上加密字面量 | 同上，且构建更慢 |
| 代码水印 | 嵌入开发者标识，追查泄露源 | **必须先开混淆** |

配置在项目根的 `code.fortify.config.json`，只对 `upload` 场景开启即可（`local`/`preview` 关掉，否则调试时堆栈全是乱码）。

限制：
- 小于 20KB 的 JS 文件加不上水印，需要先合并；
- 大于 15MB 的 JS 文件可能加固失败；
- 不要拿第三方加固过的产物二次加固。

## 三、敏感数据

- **AppSecret 绝不能出现在客户端**，签名、`access_token` 获取全部放服务端（见 `server.md`）。
- 客户端拿到的只能是 `code` / `anonymousCode`，openid 由服务端换取后下发。
- 日志里不要打印 `session_key`、`openid` 全量、支付金额明细。
- 用户手机号、身份证等敏感信息按平台「敏感数据处理」规范脱敏存储。

## 四、资质与备案

上线前必须齐备，缺一项就卡在提审：

| 项 | 说明 |
|---|---|
| 主体资质 | 企业营业执照 / 个人身份证明，经营范围要能覆盖游戏 |
| 类目 | 后台选择游戏类目，部分类目需额外资质 |
| 软件著作权 | 游戏软著，名称要与小游戏名称一致 |
| ICP 备案 | 小游戏备案申报，主体与域名都要备 |
| 版号 | 涉及付费（内购）的游戏需要版号，纯广告变现要求不同，以后台提示为准 |
| 适龄提示 | 按「小游戏适龄提示分段表」标注，并在游戏内展示 |
| 隐私政策 | 收集任何用户信息前必须展示并取得同意 |

## 五、审核常见驳回原因

| 类型 | 典型问题 |
|---|---|
| 内容 | 涉赌、涉黄、暴力血腥、诱导分享、虚假宣传 |
| 功能 | 必接能力缺失、核心玩法无法完成、频繁崩溃 |
| 交互 | 按钮遮挡、无法返回、强制观看广告 |
| 广告 | 诱导点击、广告遮挡游戏区域、误触关闭按钮 |
| 资质 | 名称与软著不一致、类目错选、缺版号 |
| 隐私 | 未弹隐私协议就收集信息 |

审核规范原文在 `docs/operation/norms/`，共 20 篇，按「基础信息 / 备案 / 资质 / 内容 / 行为 / 广告 / 内购」分类。

## 六、发布前检查清单

- [ ] 侧边栏复访已接，真机验证可跳转
- [ ] 内购游戏已接客服，能正常进入会话
- [ ] 有输入框的地方都接了敏感词过滤
- [ ] 代码加固只在 upload 场景开启，且本地产物未混淆
- [ ] AppSecret 不在客户端，签名在服务端
- [ ] 首包体积达标（分包 4MB / 不分包 20MB）
- [ ] 隐私协议首启弹出，拒绝后不采集
- [ ] 适龄提示已标注
- [ ] iOS / Android 各一台中低端机跑通主流程
- [ ] 弱网、切后台、杀进程后重进均正常
