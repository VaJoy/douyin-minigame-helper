# 支付（虚拟支付）

> **适用**：内购变现。支持「道具直购」与「游戏币」两种场景。
> **源文档**：`docs/develop/api/javascript-api/payment/`（13 篇）、`docs/develop/guide/open-ability/payment/`（2 篇）、`docs/develop/server/`。
> **关联**：下单代码见 `api-recipes.md` 第 4 节；服务端签名与回调见 `server.md`。

## 开通前置（缺一不可）

1. 开发者后台 → **虚拟支付** → 申请开通（资质不足会卡住）；
2. 签署协议、开通收款商户、填写结算账户与银行信息；
3. **设置游戏币兑换汇率** —— 提交后**不可修改**，定之前想清楚；
4. 配置**服务端回调地址**；
5. 审核通过后才能调起支付。

## 两种场景

| 场景 | `goodType` | 必传参数 | 用途 |
|---|---|---|---|
| 游戏币 | `0`（默认）/ `1` | `buyQuantity` | 先充值游戏币，再用币买道具 |
| 道具直购 | `2` | `orderAmount`（分）、`goodName`（≤10 字） | 直接买某个道具，不经过币 |

`goodType` 需要基础库 **3.47.0+**，用 `tt.canIUse('requestGamePayment.object.goodType')` 判断；不支持时退回游戏币场景。

## 下单调用

```js
tt.requestGamePayment({
  mode: 'game',
  env: 0,                 // 0 = 正式环境，无沙箱
  currencyType: 'CNY',
  platform: 'android',    // windows = PC 端
  zoneId: '1',            // 分区 ID，无分区填 '1'
  customId: orderId,      // 开发者订单号，全局唯一
  extraInfo: 'roleId=xxx',// ≤256 字符，原样回传
  buyQuantity: 60,        // 游戏币场景必传
  success(res) { /* 前端回调，仅代表调起成功 */ },
  fail(res) { /* 用户取消 / 参数错误 */ },
});
```

**游戏币场景的定价约束**：`buyQuantity × 游戏币单价` 必须正好落在平台限定价格档位上（1/3/6/8/12/18/25/30/40/45/50/60/68/73/78/88/98/108/118/128/148/168/188/198/328/648/998/1288/1998/2998 元）。不在档位内会直接报错。

> 上面只列关键字段。**完整流程**（`canIUse` 兼容道具直购、先让服务端落单再调支付）在 `api-recipes.md` 第 4 节，那份是权威版本。

## 三种结果来源，缺一不可

| 来源 | 可靠性 | 用途 |
|---|---|---|
| 前端 `success` / `fail` | 只代表「支付流程走完」 | 立刻给用户 UI 反馈 |
| 服务端支付回调 | 准，但网络异常时**不保证 100% 触达** | 发货的唯一可信依据 |
| 主动查单 `queryPayState` | 兜底 | 掉单时补查、补发 |

正确姿势：

1. 前端拿到 `success` 后**不要直接发货**，提示「到账中」并让服务端去核对；
2. 服务端收到回调 → 校验签名 → 幂等发货（按 `customId` 去重）；
3. 用户重进游戏时，服务端主动查一次最近未完成的订单，补发。

## 掉单与延迟

- 支付成功后游戏币可能延迟到账，建议前端在回调后**每 3 秒轮询一次余额、持续约 1 分钟**，用 `save_amt` 变化判断是否到账。
- 进游戏时允许主动刷新余额，但**不要把查余额做成进入游戏的前置条件**，查询失败也不要显示 0。
- `customId` 不传或重复，回调里就没有订单号，直接导致无法发货 —— 这是最常见的掉单原因。

## 平台差异

- **PC 端只支持钻石支付**，`platform: 'windows'`。
- iOS 端受苹果政策约束，虚拟支付能力与安卓不同，上线前确认当前宿主支持情况。
- 支付必须在登录态下发起，先 `tt.checkSession` 再下单。

## 退款与对账

- 未成年人退款走后台流程，见 `references/ops.md` 与 `docs/operation/agreement-and-norms/`；
- 对账以服务端流水为准，客户端不保存任何金额逻辑；
- 结算比例与开票见 `ops.md`。
