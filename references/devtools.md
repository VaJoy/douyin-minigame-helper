# 开发者工具

> **适用**：抖音小游戏开发者工具的日常使用与调试技巧。
> **源文档**：`docs/develop/dev-tools/`（29 篇）。
> **关联**：导出流程见 `quickstart.md`；加固配置见 `security-release.md`。

## 版本与下载

- 从开放平台「开发者工具下载」页取最新版；分包、抖音云、代码保护等功能对工具版本有硬要求（分包需 ≥2.0.6，抖音云需 ≥4.3.4，深度防护需 ≥4.3.5）。
- 工具只用于**开发调试**，最终表现以真机为准，不要拿模拟器结论当线上结论。

## 导入项目

「导入项目」指向**构建产物目录**（含 `game.js` / `game.json` / `project.config.json`），不是引擎工程目录。缺 `project.config.json` 时工具会自动补，记得把 AppID 填对。

## 编译设置

| 选项 | 作用 |
|---|---|
| ES6 → ES5 | 兼容老设备；关掉后低版本宿主可能语法报错 |
| 代码压缩 | 减小包体，但会打乱堆栈 |
| Source Map | 排线上错误必备，压缩后仍能定位到源码行 |

建议：**开发关压缩开 sourcemap，上传开压缩**。

## 调试手段

### 1. 模拟器

工具内直接运行，改代码即时生效。适合调 UI 和逻辑，不适合判断性能与音频/广告行为。

### 2. 真机预览

点「预览」生成二维码，用抖音扫码。这是最接近线上的验证方式。

### 3. 彩蛋页：全入口指定版本（排线上入口问题）

线上「从某个入口进就白屏、扫码却正常」这类问题，靠它定位：

1. 控制台 → 开发设置 → 测试管理，扫码把设备加入测试账号（每个应用最多 100 台）；
2. 抖音里「我 → 更多功能 → 开发者模式」，打开开关（Android 需重启生效）；
3. 进入目标小游戏详情页，打开「全入口打开指定版本小游戏」，选择「IDE 上传的测试版本」或扫码选预览版本；
4. 重启抖音，之后从**任何入口**进入都是你指定的版本。

### 4. vConsole / 实时日志

- vConsole：真机上的控制台，看 `console.log` 与网络请求。
- 实时日志：把线上真机日志回传后台，排查用户侧问题（性能文档里也有说明）。

### 5. 抖音云本地调试

工具 4.3.4+ 支持在本地创建/调试云函数：项目里配 `cloudfunctionRoot` 指向函数目录，右键可「同步函数服务」「新建函数服务」「本地调试函数服务」。

### 6. Lite 模式（4.1.0+）

习惯用 VSCode 写代码的话建议开：省内存 **30%+**，真机调试的步骤也更短。

- 开启：窗口右上角「Lite 模式」按钮，或模拟器横幅按钮；设置里可勾选「以 Lite 模式打开新工程」。
- 每个工程会记住上次退出时的模式，不会全局生效。

## TypeScript 类型提示

用 TS 写的话装官方类型包，`tt.*` 就有补全和类型检查：

```bash
npm install @douyin-minigame/api-typings
```

```json
// tsconfig.json
{ "compilerOptions": { "types": ["@douyin-minigame/api-typings"] } }
```

也可以 `import '@douyin-minigame/api-typings';` 或三斜杠引用。**类型声明与文档站冲突时以文档为准**（官方明确这么说，类型包偶尔滞后）。

## 代码保护（深度防护）

工具内「实验 → 游戏深度防护 → 初始化配置」，在项目根生成 `code.fortify.config.json`：

```json
{
  "enable": { "local": false, "preview": false, "upload": true },
  "watermark": { "name": "水印保护", "files": [] },
  "obfuscation": {
    "name": "代码混淆",
    "tasks": [
      { "level": 3, "files": ["game.js", "js/core.js"] }
    ]
  }
}
```

- `enable` 分场景：`local` 模拟器、`preview` 真机预览、`upload` 上传。通常只开 `upload`。
- `level` 1~3，等级越高体积越大、性能开销越高；无特殊要求建议 3。
- **开水印必须先开混淆**；小于 20KB 的 JS 可能被跳过水印，大于 15MB 的 JS 可能加固失败。
- 不要拿第三方加固过的产物再加固一次（兼容性与安全风险）。

## 协作与版本

- 工程目录建议纳入 Git；构建产物（`build/`、`library/`、`temp/`）不要提交。
- 小游戏本体没有「分支」概念，多环境靠后台的**开发版 / 测试版 / 线上版**三档区分。
- 灰度发布在后台按比例放量，期间新旧版本共存，服务端协议要兼容旧客户端。
